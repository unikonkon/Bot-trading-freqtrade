# SMC Adaptive Short trade — Spot ระยะสั้น

เพิ่มกลยุทธ์ `smc_adaptive_short` ใน [`lib/indicators.ts`](../../../lib/indicators.ts) และ [`lib/backtest.ts`](../../../lib/backtest.ts) แล้ว ชื่อในเว็บคือ **SMC Adaptive Short trade**. ตามคำยืนยันของผู้ใช้ เป็นการซื้อแล้วขาย Spot ระยะสั้น ไม่ใช่เปิดสถานะ Short. กลยุทธ์ V1/V2 เดิมยังอยู่และสัญญาณไม่เปลี่ยนจากก่อนเพิ่มตัวนี้.

ผล BTCUSDT 1,000 แท่งปิดล่าสุดต่อ timeframe ดีกว่า V2 ในหน้าต่างเดียวกัน แต่ **ยังไม่ใช่กำไรทุกช่วง**: 5m/15m เป็นบวก, 3m ติดลบหลังต้นทุน และ 1m ไม่มีเทรด. การถือเงินสดใน 1m ไม่ใช่หลักฐานว่ากลยุทธ์มีความได้เปรียบในการเทรด 1m.

ใช้ next-open: สัญญาณที่ปิดแท่งส่งไปซื้อ/ขายที่เปิดแท่งถัดไป, fee 0.10% และ adverse slippage 0.05% ต่อขาทั้งซื้อและขาย. Long-only หนึ่งสถานะ เริ่มเงิน 100 หน่วย ใช้เงินทั้งพอร์ตต่อเทรด ไม่มี leverage และปิดสถานะค้างที่ราคาปิดแท่งสุดท้ายพร้อมต้นทุน. ไม่ปรับวิธีคิดเงินของ engine เพื่อเพิ่มผลกำไร.

**แนวคิดและกติกาที่เพิ่ม**

1. **SMC liquidity sweep + micro reversal:** รอ low กวาดใต้ internal pivot low ที่ยืนยันแล้ว แต่ปิดกลับเหนือระดับนั้นเป็นแท่งเขียว จากนั้นภายใน 5 แท่งต้องปิดเหนือ high แท่งก่อนหน้าและ RSI เพิ่ม. หากปิดหลุด support เกิน 0.25 ATR จะล้าง setup. เป็นการใช้รูปแบบราคาเป็นตัวแทนการกวาดสภาพคล่อง ไม่ได้ยืนยันคำสั่งซื้อขายของสถาบันจากข้อมูล order book.
2. **SMC bullish break + retest:** หลัง bullish BOS/CHoCH ยืนยันแล้ว รอแท่งถัดไปย่อแตะระดับ break ภายในระยะ 0.25 ATR และปิดกลับเหนือระดับนั้นภายใน 5 แท่ง ต้องเป็นแนวโน้มขึ้นจาก EMA21/55 และ DI. ไม่ซื้อทันทีเพียงเพราะแท่งทะลุแนวต้าน.
3. ทั้งสองแบบต้องเป็นแท่งเขียว ปิดสูงกว่าแท่งก่อนและอยู่บริเวณ 60% บนของช่วง high–low, RSI < 65, ระยะเหนือ EMA21 ไม่เกิน 1.5 ATR, volume ≥ 0.8 เท่าของค่าเฉลี่ย **20 แท่งก่อนหน้า**. ไม่รวม volume แท่งปัจจุบันไว้ในค่าเฉลี่ยอ้างอิง.
4. งดซื้อเมื่อ EMA/DI บ่งชี้ขาลงและ ADX ≥ 25. ADX25 ในสูตรนี้เป็นตัวกรอง **ขาลงแรง** ไม่ใช่ข้อบังคับให้ทุก BUY ต้อง ADX≥25 จึงยังรองรับการกลับตัวในตลาดแกว่งตัวที่ไม่ใช่ขาลงแรง.
5. งดเข้าและพักเมื่อ True Range > 3.5 เท่าของ ATR แท่งก่อน หรือ ATR เร็ว/ช้า > 2.2. พักต่อจนห่างจากแท่ง shock เกิน 3 แท่ง และล้าง setup เดิม. รวม gap ไว้ใน True Range.
6. ระยะ stop เริ่มต้น = max(1.2 ATR, ระยะถึง low ของ setup + 0.15 ATR, 0.08% ของราคา). เป้าหมาย = min(14 ATR, ระยะถึง swing resistance เหนือราคา − 0.1 ATR). หากไม่มีแนวต้านเหนือราคา ใช้ระยะ 14 ATR เป็นการประมาณจากความผันผวน. **14 ATR เป็นเพดานเป้าหมาย ไม่ใช่ผลตอบแทนที่คาดว่าจะได้แน่นอน** และไม่ได้หมายถึงถือจนถึงเป้านั้นทุกเทรด.
7. ก่อนเข้า เผื่อต้นทุนไป–กลับ `costPct=0.31%`: กำไรที่เหลือถึงเป้าหลังต้นทุนต้อง ≥0.08% ของราคา และ `(reward − cost)/(risk + cost) ≥ 0.75`. หากไม่ผ่านให้งดเข้า ไม่ย้ายเป้าหมายไกลขึ้นเพื่อทำให้ตัวเลขผ่าน.
8. ออกเมื่อราคาปิดถึง stop/target, SMC กลับเป็น bearish และปิดต่ำกว่า EMA21 หรือถือครบ **48 แท่ง**. เริ่มเลื่อน stop ป้องกันกำไรเมื่อ peak close สูงกว่าราคาเข้าสัญญาณอย่างน้อย cost + entryATR; stop เลื่อนขึ้นเท่านั้น. พักหลังออกเกิน 3 แท่งก่อนเข้าใหม่.

Stop/target ใช้ **ราคาปิดแท่ง** แล้ว engine fill ที่เปิดแท่งถัดไป ไม่ใช่คำสั่ง stop/limit ระหว่างแท่ง. ราคาอาจกระโดดผ่าน stop และ buffer ไม่รับประกัน break-even. ระยะ stop เป็นเปอร์เซ็นต์ราคา ไม่ใช่การจำกัดความเสี่ยงเงินในบัญชีด้วย position sizing.

“ระยะสั้น” ของค่าเริ่มต้นนี้ถือสูงสุด 48 นาทีใน 1m, 2 ชั่วโมง 24 นาทีใน 3m, 4 ชั่วโมงใน 5m และ 12 ชั่วโมงใน 15m. ผลจริงรอบนี้ถือเฉลี่ยตามตารางข้างบน. จึงไม่ใช่สูตรที่รับประกันว่าจะปิดทุกดีลภายในไม่กี่นาที.

**ต้นทุนที่ใช้กรองกับต้นทุนที่ engine หัก**

`costPct` เป็นพารามิเตอร์ของ indicator ตั้งแยกจาก fee/slippage ของ backtest เพื่อให้เรียกสูตรจาก `indicators.ts` ได้โดยไม่ผูกกับ engine. ค่าเริ่มต้น 0.31% เผื่อมากกว่าระยะราคาประมาณ 0.30045% ที่ต้องชดเชย fee0.10% + slippage0.05% ต่อขาในสมมติฐานนี้เล็กน้อย. หากเพิ่มต้นทุนในเว็บ ต้องปรับ `costPct` ให้ครอบคลุมด้วย. เว็บจะแสดงข้อความเมื่อค่าที่เผื่อไว้น้อยกว่าต้นทุนที่ตั้ง แต่ไม่เปลี่ยนพารามิเตอร์ให้เอง.

ต้นทุนจริงขึ้นกับบัญชี วิธีส่งคำสั่ง สภาพคล่อง และสภาพตลาด; ไม่มีข้อมูล order book สำหรับวัด fill จริงในชุดนี้. หลักการพิจารณาสเปรดและความผันผวนประกอบต้นทุนอ้างอิง [CME: Liquidity and Immediacy](https://www.cmegroup.com/education/courses/trading-and-analysis/liquidity-and-immediacy). การตั้ง cost gate และค่าตัวเลขเป็นการออกแบบของโครงการ ไม่ใช่สูตรรับรองจาก CME.

**สิ่งที่ผลบอกได้**

1m: ไม่มี BUY. มี 9 แท่งที่ผ่าน setup/ตัวกรองก่อนหน้าแล้วติด cost gate; อีกหลายแท่งติด volume, แนวโน้ม, shock หรือไม่มี setup. การรอในสภาพนี้ลดการจ่ายต้นทุน แต่ยังไม่มีข้อมูลเทรดจริงพอพิสูจน์คุณภาพของสูตรบน 1m.

3m: ชนะ 2 จาก 3 แต่กำไรก่อนต้นทุน +0.81% กลายเป็น −0.09% สุทธิ. หนึ่งเทรดกำไรสุทธิเพียง +0.00007% จึงอ่อนไหวต่อต้นทุนมาก. อัตราชนะสูงไม่ได้หมายถึงกำไรสุทธิเป็นบวก.

5m: 2 เทรด ได้แก่ liquidity sweep +0.6281% และ SMC retest −0.1280%. กำไรสุทธิรวม +0.4993% จึงพึ่งเทรดชนะครั้งเดียว. Development ของ 5m ทั้งสองหน้าต่างติดลบ ยังสรุปความสม่ำเสมอไม่ได้.

15m: 7 เทรดทั้งหมดเป็น liquidity sweep. เทรดวันที่ 11 กันยายนให้ +2.5560% และวันที่ 14 กันยายน +1.0196%; มีเทรดอื่นขาดทุนรวมอยู่ด้วย. หากเอาเทรดที่ดีที่สุดออก พอร์ตที่เหลือจะเป็น −0.6872%. ผล train/validation/final รอบนี้เป็นบวกทั้งสามช่วง แต่จำนวนเทรดยังน้อยและยังต้องตรวจข้อมูลใหม่ที่ไม่เคยใช้ในการออกแบบก่อนสรุปความได้เปรียบ.

เมื่อตั้ง slippage เป็น 0.10% ต่อขา โดย fee คง 0.10% และคงสัญญาณเดิม: 1m 0.00% (0 เทรด), 3m −0.39%, 5m +0.30%, 15m +1.14%. เป็น stress test ของต้นทุน fill ไม่ได้ปรับ cost gate ตามค่า slippage ใหม่ในตารางนี้.

**ความรู้เพิ่มเติมที่นำมาใช้**

RSI เป็นตัววัดโมเมนตัมและอาจค้างในเขต oversold/overbought ระหว่างแนวโน้มแรงได้ จึงไม่ซื้อเพราะ RSI ต่ำเพียงอย่างเดียว แต่รอ price reclaim และงดซื้อในขาลงแรง. อ้างอิง [Fidelity: RSI](https://www.fidelity.com/learning-center/trading-investing/technical-analysis/technical-indicator-guide/RSI).

ADX ช่วยวัดความแรงของแนวโน้มและ DI ช่วยด้านทิศทาง; สูตรนี้ใช้ร่วมกับ EMA เพื่อแยกขาลงแรงจากการแกว่งตัว. อ้างอิง [Fidelity: DMI/ADX](https://www.fidelity.com/learning-center/trading-investing/technical-analysis/technical-indicator-guide/DMI). ATR ใช้ปรับระยะตามความผันผวน ไม่ใช่ตัวบอกว่าราคาจะขึ้น: [Fidelity: ATR](https://www.fidelity.com/learning-center/trading-investing/technical-analysis/technical-indicator-guide/atr).

ทดสอบผลเมื่อเอาแท่งอนาคตออกเพื่อค้นหา lookahead ด้วย harness ของโครงการเอง ตามหลักการตรวจความต่างของผลคำนวณ: [Freqtrade: Lookahead analysis](https://www.freqtrade.io/en/stable/lookahead-analysis/). ข้อมูลมาจาก [Binance Spot REST API](https://github.com/binance/binance-spot-api-docs/blob/master/rest-api.md).

**ตรวจและใช้งาน**

`npm run web:check` ผ่าน. `npm run web:test` ผ่าน 44 tests รวม 8 tests ของ Short trade สำหรับ cost gate, volume แท่งก่อน, shock cooldown, time exit, gap, warmup, export และ parameter validation. ตรวจทุก prefix ของ final test 4 ช่วงผ่าน 4,004 กรณี; สัญญาณอีก 12 กลยุทธ์เหมือน snapshot ก่อนเพิ่มครบ 48 การเปรียบเทียบ. Export รายแท่ง/เหตุผล/ผลจำลองตรงกับ `computeSignals` และ engine.

`npm run typecheck` ทั้ง repository ยังไม่ผ่านจาก dependencies ที่ไม่มีอยู่ในโครงการเดิม: `next/server`, `clsx`, `tailwind-merge` และชนิด `RequestInit.next` ของ API เก่า. ไม่มีการติดตั้ง framework เพิ่มเพื่อแก้ไฟล์ที่ไม่เกี่ยวกับเว็บทดสอบนี้.

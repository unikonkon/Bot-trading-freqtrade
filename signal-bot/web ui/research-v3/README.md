# research-v3 — สคริปต์วัดผลของกลยุทธ์ v3

ใช้ข้อมูลใน `data-test/BTCUSDT/btcusdt-20260917/` (BTCUSDT เต็มปี 17 ก.ย. 2025 – 17 ก.ย. 2026)
ทุกสคริปต์เริ่มนับผลหลัง warm-up 1,000 แท่ง และเติม `exposure` เข้า `simulateExposure` แบบ next-open

**การแบ่งข้อมูล** (`lib.ts`) — train คือก่อน 17 พ.ค. 2026, test คือหลังจากนั้น
ช่วง test ได้ warm-up ของตัวเองจากแท่งก่อนหน้า จึงไม่มี indicator รั่วข้ามช่วง
**ค่าพารามิเตอร์ทุกตัวถูกเลือกจาก train เท่านั้น** ส่วน test ใช้รายงานผลอย่างเดียว

| ไฟล์ | ตอบคำถามอะไร |
|---|---|
| `lib.ts` | โหลดข้อมูล แบ่ง train/test คำนวณ t-statistic |
| `shorttrade-baseline.ts` | **อินดิเคเตอร์ SMC ที่ใช้เป็นเส้นฐาน** ย้ายออกจาก `lib/` มาที่นี่เพราะไม่ใช่โค้ดของผลิตภัณฑ์แล้ว — `diagnose` / `entry-edge` / `scan` / `search` / `pick-defaults` / `final-report` เรียกใช้ |
| `diagnose.ts` | ความได้เปรียบก่อนหักต้นทุน ซ่อนอยู่ในกลุ่มย่อยไหน (setup / ทิศ / regime / ชั่วโมง / ADX / ความมั่นใจ / เวลาถือ) |
| `scan.ts` | ปรับพารามิเตอร์ที่มีอยู่เดิมอย่างเดียวพอให้เป็นบวกไหม |
| `search.ts` | ค้นหาบน train แล้ววัดบน test พร้อมสหสัมพันธ์ train↔test ใน 3 โครงสร้างต้นทุน |
| `entry-edge.ts` | **การทดสอบที่ชี้ขาด** — จังหวะเข้าทำนายทิศทางได้ไหม โดยไม่เกี่ยวกับกฎการออก |
| `alt-signals.ts` | มีสัญญาณชนิดอื่น (กลับตัว / โมเมนตัม / RSI / เทรนด์ / ทะลุกรอบ) ที่รอดข้าม train→test ไหม |
| `thrust-check.ts` | ตรวจสัญญาณ "เหวี่ยงแรงแล้วไปต่อ" แบบ end-to-end พร้อมค่าธรรมเนียม |
| `thrust-surface.ts` | สัญญาณนั้นเป็นที่ราบ (แกร่ง) หรือยอดแหลม (บังเอิญ) |
| `thrust-clock.ts` | ความได้เปรียบอยู่ที่เวลาจริงหรือจำนวนแท่ง |
| `pick-defaults.ts` | เลือกค่าตั้งต้นของกลไกใหม่จาก train แล้วดูผลบน test |
| `final-report.ts` | ผลเต็มปีของ ShortTrade V3 ทุก timeframe และทุกทิศ (เรียก `shorttrade-baseline.ts` ตรง เพราะไม่ได้ลงทะเบียนแล้ว) |

### ชุดที่สอง — หาที่มาของสัญญาณใหม่ จนได้กลยุทธ์ที่เป็นบวก

| ไฟล์ | ตอบคำถามอะไร |
|---|---|
| `screen.ts` | คัดกรองค่าทำนายหลายตระกูลด้วย Information Coefficient ก่อนเขียนกฎใด ๆ |
| `ofi-validate.ts` | แก้ t-stat ที่ถูกเป่าให้ใหญ่เกินจริงจากหน้าต่างผลตอบแทนที่ซ้อนทับกัน |
| `ofi-backtest.ts` | ทดสอบแรงซื้อขายสุทธิแบบ end-to-end พร้อมค่าธรรมเนียม |
| `ofi-clock.ts` | ความได้เปรียบอยู่ที่ช่วงย้อนหลังเป็นเวลาจริงหรือจำนวนแท่ง |
| `ofi-demean.ts` | **สำคัญ** — สัญญาณมีอคติไปข้างเดียวถาวรหรือไม่ และการลบค่าเฉลี่ยของตัวเองแก้ได้ไหม |
| `ofi-surface.ts` | ที่ราบของพารามิเตอร์หลังลบอคติ (ป้องกันการหยิบยอดแหลม) |
| `ofi-audit.ts` | **สำคัญ** — ได้กำไรเพราะทำนายถูก หรือเพราะขายในตลาดขาลงเฉย ๆ (เทียบกับเส้นฐาน "ขายตลอดเวลา") |
| `ofi-crosscoin.ts` | ทดสอบบนเหรียญที่ไม่เคยถูกใช้เลือกค่าเลย |
| `ofi-portfolio.ts` | ผลแบบพอร์ตแบ่งทุนเท่ากันหลายเหรียญ ซึ่งเป็นวิธีที่จะใช้จริง |
| `orderflow-report.ts` | ผลของกลยุทธ์ที่ลงทะเบียนแล้วทั้งสามรหัส (สองทาง / ซื้อ / ขาย) ผ่านเส้นทางโค้ดเดียวกับเว็บ |

### ชุดที่สาม — โปรไฟล์ของแต่ละ timeframe เพื่อใช้วางแผนเข้า-ออก (ไม่ผูกกับกลยุทธ์ใด)

| ไฟล์ | ตอบคำถามอะไร |
|---|---|
| `tf-profile.ts` | ขนาด ATR เทียบต้นทุน / โครงสร้างผลตอบแทน / MFE-MAE / เวลาถึงต้นทุน / ชั่วโมงของวัน / ภาระต้นทุนตามความถี่ |
| `tf-barriers.ts` | เข้าไม้แบบสุ่มทุกแท่ง แล้ววัดว่ากฎ stop/target แบบไหนต้องชนะกี่ % จึงเสมอตัว และช่วง 13-17 UTC ต่างจากนอกช่วงอย่างไร |
| `tf-holdtime.ts` | ราคาใช้เวลาจริงเท่าไรกว่าจะเดินทางถึงระยะ stop ที่ต้นทุนแต่ละแบบบังคับ |
| `tradeplan-eval.ts` | **วัดตระกูล TradePlan ก่อนลงทะเบียน** — จังหวะเข้ามีทิศทางไหม / ผลหลังต้นทุนเทียบ OrderFlow และเส้นฐานถือฝั่งเดียว / ที่ราบพารามิเตอร์ / ปิดข้อจำกัดทีละข้อ |
| `combo-edge.ts` | **ประตูกรองทิศทางจาก OrderFlow เพิ่มข้อมูลให้ตัวเร็วไหม** — วัดผลตอบแทนล่วงหน้าของ Trendlines / EMA Cross / UT Bot / MACD / Supertrend / SMC แยกตามว่าแรงซื้อขายสุทธิเห็นด้วยหรือค้าน |
| `flowgate-eval.ts` | **วัดตระกูล FlowGate ก่อนลงทะเบียน** — ผลบน BTCUSDT / ที่ราบของ band / ตรวจข้ามเหรียญ พร้อมเกณฑ์สามข้อที่เขียนไว้ก่อนรันครั้งแรก |
| `flowgate-transfer.ts` | **ทำไม FlowGate ย้ายข้ามเหรียญไม่ได้** — ตรวจสมมติฐาน "ค่าตัวเร็วเหมาะกับความผันผวนของ BTC เท่านั้น" สามข้อตามลำดับ แล้วสรุปว่าสมมติฐานนั้นผิด |
| `flowgate-ladder.ts` | **บันไดแยกสาเหตุ** — เปลี่ยนทีละอย่างเดียวจาก OrderFlow เปล่า ๆ ไปถึง FlowGate เต็มรูปแบบ ชี้ว่ากฎการออกที่ขอบ band คือตัวปัญหา ไม่ใช่ชั้นจังหวะ |
| `flowgate-exit-select.ts` | **เลือก `gateExitMult` จาก train เท่านั้น** แล้ววัดด่านข้ามเหรียญใหม่ พร้อมเกณฑ์สี่ข้อที่เขียนไว้ก่อนรัน — ผลคือ `flowgate_utbot_v3` ถูกลงทะเบียน |
| `signal-rate.ts` | **ทำไม v3 ไม่มีสัญญาณในช่วงสั้น** — แท่งที่ต้องสะสมเทียบกับที่ดึงสดได้ · ความถี่จริงของสัญญาณ · ต้นทุนของการเพิ่มความถี่ · และความถี่เมื่อรันหลายเหรียญ |
| `fast-window-select.ts` | **หาหน้าต่างที่สั้นพอจะให้สัญญาณถี่ขึ้น** — กวาด 10 x 11 ค่าบน train เท่านั้น แล้ววัดด่าน test และข้ามเหรียญ ผลคือย่นหน้าต่างทำลายความได้เปรียบ จึงไม่ลงทะเบียน |
| `frequency-frontier.ts` | **เส้นขอบเขตความถี่–กำไร** — ที่แต่ละระดับสัญญาณ/วัน ทำกำไรบน train ได้ดีที่สุดเท่าไร (กวาดสี่แกน) |
| `frequent-select.ts` | **เลือกชุดค่าที่ถี่ ≥1 สัญญาณ/วัน จาก BTCUSDT** แล้ววัด test และข้ามเหรียญ — ตกด่านข้ามเหรียญ 0/4 ไม่ลงทะเบียน |
| `frequent-pooled.ts` | **เลือกจาก 5 เหรียญพร้อมกัน** แล้วตัดสินที่ช่วงหลัง 17 พ.ค. — พอร์ตบวก 0/6 ไม่ลงทะเบียน (ต้องดึง BTCUSDT จาก 1 พ.ค. 2025 ก่อน ดูหัวไฟล์) |
| `bar-scaling.ts` | **"ยิ่งแท่งเยอะ ยิ่งเทรดเยอะ" — กำไรโตตามไหม** นับหน้าต่างเป็นแท่ง (240/5,760) ทุก timeframe 1s–30m แล้วแยก gross/ไม้ · net taker · net maker ของ v3 และ v4 ทุกรหัส (รับไฟล์ 1s เป็นอาร์กิวเมนต์ · `ONLY_1S=1` รันเฉพาะ 1s) |
| `pooled-lead-check.ts` | ตรวจ lead 4/40/0.01/0 จาก `frequent-pooled.ts` ครั้งเดียวบนช่วงหลัง 17 พ.ค. — บวก 6/6 แต่แพ้ `orderflow_v3` จึงไม่ลงทะเบียน |
| `flowgate-confirm.ts` | **ยืนยันว่าไม่ใช่ยอดแหลม** — ช่องข้างเคียงของทุกพารามิเตอร์ ผลรายเหรียญ เส้นฐานถือฝั่งเดียว และการตรวจไม่มองอนาคต |
| `flow-exit-select.ts` | **เลือกกฎการออกของ OrderFlow จาก train เท่านั้น แล้วตัดสินว่าควรลงทะเบียนไหม** — เกณฑ์สามข้อเขียนไว้ในหัวไฟล์ก่อนรันครั้งแรก และสคริปต์พิมพ์คำตัดสินเอง เป็นที่มาของรหัส `orderflow_v3_zero` |

ข้อมูลเหรียญอื่นของชุดนี้ดึงด้วย `npx tsx scripts/download-crosscoin.ts` ซึ่งเริ่มไฟล์ที่ 1 พ.ค. 2025
ย้อนไปไกลกว่าชุด BTCUSDT ราว 4 เดือนครึ่งโดยตั้งใจ เพื่อให้ทุกเหรียญเริ่มนับผลวันเดียวกับ BTCUSDT
หลังหักช่วงสะสม 125 วันของสัญญาณไปแล้ว (ถ้าเริ่มพร้อมกัน ช่วงประเมินผลจะสั้นกว่าและเทียบกันไม่ได้)
